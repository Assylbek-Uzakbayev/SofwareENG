## 8. Conclusion

In this lab experiment, we evaluated how different prompt engineering techniques affect the quality and safety of Python code generated by Large Language Models.

Prompt A provided a minimal description, resulting in basic functional code without type validation or proper error handling. Prompt B introduced clear type hints and docstrings, improving code structure but failing to protect against invalid input types or out-of-range values. Prompt C added concrete examples, which helped the model enforce the expected dictionary format and handle empty input lists correctly. However, it still allowed invalid data types to throw unhandled `TypeError` exceptions instead of explicit `ValueError` exceptions.

Prompt D achieved the highest accuracy (8/8) by explicitly specifying validation rules, expected exception types (`ValueError`), and edge-case boundaries (0 to 100 range and numeric checks). The test runner results confirmed that Prompt D passed all 6 test cases, whereas Prompts A, B, and C failed during string input and out-of-range value scenarios. In conclusion, detailed specification of boundary conditions and explicit exception requirements in prompts are critical for generating robust, production-ready code.
